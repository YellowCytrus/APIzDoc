# Иерархия директорий в проекте

Короткий справочник, чтобы быстрее находить нужный код/конфиги по названию директории.

## Корень репозитория

- `app/` — бэкенд на FastAPI (маршруты, модели, генерация PDF).
- `frontend/` — фронтенд редактора (Vue3 + Vite + TypeScript).
- `docs/` — вспомогательная документация по API/CI.
- `tests/` — автоматические тесты сервиса (быстрые и интеграционные).
- `alembic/` — миграции базы данных (schema evolution через Alembic).
- `scripts/` — утилиты/скрипты для разовых задач (например, конвертация/импорт).
- `fonts/` — пользовательские шрифты Typst (монтируются в контейнер).
- `images/` — изображения, которые могут использоваться в документации/материалах.
- `docker-compose.yml`, `Dockerfile` — запуск сервисов в Docker.
- `local_docker_start.sh` — удобный локальный запуск через Docker.

## Бэкенд: `app/`

Структура внутри `app/` разделяет “контракты/маршруты”, “данные” и “инструменты”:

- `app/api/` — REST API: обработчики запросов и сборка ответа (в т.ч. генерация PDF).
  - `app/api/elements/` — обработка стилизации различных типов элементов.
  - `app/api/generate.py` — “склейка” входного Markdown, применением профиля и генерацией PDF.
- `app/models/` — модели/схемы данных.
  - `app/models/sqlalchemy/` — SQLAlchemy-модели и маппинг таблиц.
  - `app/models/sqlalchemy/styles/` — наборы стилевых сущностей (списки, заголовки, страницы и т.д.).
- `app/repositories/` — доступ к данным через репозитории (профили, стили, титульные страницы).
- `app/utils/` — инфраструктурные утилиты:
  - `typst_preamble.py` — построение Typst-предисловия (preamble) из стилей профиля (`#set ...`).
  - `pandoc_converter.py` — конвертация Markdown → исходник Typst (строка Typst-кода).
  - `typst_compiler.py` — компиляция Typst → PDF через CLI `typst compile`.
- `app/main.py` — точка входа приложения.
- `app/deps.py` и `app/database.py` — зависимости FastAPI и работа с БД.

## Документация

- `README.md` — основной “стартовый” документ: запуск, стек, тесты, ссылки.
- `docs/API.md` — подробности REST API (эндпоинты, схемы, ответы).
- `docs/CI_AND_PROTECTION.md` — как устроены CI (GitHub Actions) и рекомендации по branch protection.

## Фронтенд: `frontend/`

- `frontend/src/` — исходники редактора: компоненты, composables и логика UI.
- `frontend/public/` и `frontend/dist/` — статика/результат сборки (зависит от сценария).
- `frontend/package.json` — зависимости и скрипты сборки/запуска Vite.

## Миграции: `alembic/`

Если нужно изменить структуру БД:
- шаблоны/скрипты миграций живут в `alembic/versions/`;
- запуск миграций обычно привязан к механике приложения/контейнера (см. в `README.md` и конфиги проекта).

## Тесты: `tests/`

Тесты лежат в `tests/` и разделяются по типам:
- быстрые проверки публичного API без реального `pandoc/typst`;
- интеграционные сценарии с полной генерацией (маркированы соответствующими метками в запуске pytest).
